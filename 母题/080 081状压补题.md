# 080081状压补题

Content frame: 080/081 这一组母题都在训练同一件事：把“已经选了什么、满足了什么、访问了什么、还剩什么”压成二进制状态。Key point: 先判断二进制位代表什么，再谈转移；位的含义错了，后面的 DP 都会歪。

---

## 母题：[[080 Code01 我能赢吗]]

Mother-problem diagnosis: 这是集合状态上的博弈题。状态表示还能选哪些数，任务不是求最大收益，而是判断当前玩家是否存在一步能把对手送进必败状态。

Method core: `status + 记忆化搜索`。站在当前先手视角枚举下一步，只要有一个后继状态让对手输，当前状态就赢。

Selection lens: Model discriminator and unit recognition。这里要先分清“一个动作”是什么：动作是选一个还没用过的数字，状态变化是删除这个数字。

Test point: 胜负递归的返回值必须始终表示“当前行动者能不能赢”，不要混成“先手能不能赢”。

Variants:
- Example problem: [LeetCode 526. 优美的排列](https://leetcode.cn/problems/beautiful-arrangement/)  
  Same-shell variant: 仍然是“哪些数字已经使用”的状态，只是胜负目标换成合法排列计数。
- Changed-entry variant: [LeetCode 2741. 特别的排列](https://leetcode.cn/problems/special-permutations/)  
  Changed dimension: 需要额外记录上一个数字，状态从 `status` 升级成 `status + last`。

Method summary: 看到“不能重复选、每一步从剩余集合里挑一个”，先尝试用 `status` 表示剩余或已选集合，再决定要不要加 `last / rest / score`。

## 母题：[[080 Code02 火柴拼正方形]]、[[080 Code03 划分为k个相等的子集]]

Mother-problem diagnosis: 这是子集装桶题。题面看起来是分组，真正的状态是“哪些物品已经被放进桶里”。

Method core: `status + 当前桶容量` 或 `status -> 当前桶余量`。把一个桶装满后进入下一个桶，同一个 `status` 要能复用。

Selection lens: Invariant-condition checklist。总和能否整除、单个物品是否超过桶容量、空桶/满桶边界，都是方法能不能成立的前置检查。

Test point: Key point: 不要把桶编号当成核心状态；桶之间往往是等价的，真正能去重的是物品使用集合。

Variants:
- Same-shell variant: [LeetCode 1986. 完成任务的最少工作时间段](https://leetcode.cn/problems/minimum-number-of-work-sessions-to-finish-the-tasks/)  
  Changed dimension: 桶数从固定目标变成最少桶数。
- Hidden-condition variant: [P3052 [USACO12MAR] Cows in a Skyscraper G](https://www.luogu.com.cn/problem/P3052)  
  Changed dimension: 同样是装桶，但更强调容量上限和最少电梯数。
- Lens-specific upgrade variant: [LeetCode 2305. 公平分发饼干](https://leetcode.cn/problems/fair-distribution-of-cookies/)  
  Changed dimension: 目标从“可不可行”变成“最大桶负载最小”。
- Comprehensive variant: [P3092 [USACO13NOV] No Change G](https://www.luogu.com.cn/problem/P3092)  
  Changed dimension: 仍然压商品集合，但外层资源变成硬币/支付能力。

Method summary: 装桶类状压先做三件事：检查总量和单件边界，确定 `status` 表示已装物品，最后决定目标是可行、最少桶数还是最小最大负载。

## 母题：[[080 Code04 售货员的难题 - TSP问题（普通版）]]

Mother-problem diagnosis: 这是访问全集的路径最优化。状态不能只说访问了哪些点，还要说最后停在哪个点。

Method core: `dp[status][last]`。`status` 表示访问集合，`last` 表示当前路径末尾，转移时枚举上一个点或下一个点。

Selection lens: Transform-to-solvable。把“排列所有访问顺序”变成“访问集合 + 末尾点”的状态转移，避免直接枚举全排列。

Test point: Key point: TSP 的本质不是排列题，而是“排列前缀可以被访问集合压缩”。

Variants:
- Same-shell variant: [P1433 吃奶酪](https://www.luogu.com.cn/problem/P1433)  
  Changed dimension: 图边权来自几何距离，状态模型不变。
- Changed-question variant: [LeetCode 847. 访问所有节点的最短路径](https://leetcode.cn/problems/shortest-path-visiting-all-nodes/)  
  Changed dimension: 从固定起点最短回路变成任意起点访问全集最短路。
- Changed-representation variant: [LeetCode 943. 最短超级串](https://leetcode.cn/problems/find-the-shortest-superstring/)  
  Changed dimension: 点之间的“距离”变成字符串拼接代价。
- Comprehensive variant: [P3959 [NOIP2017 提高组] 宝藏](https://www.luogu.com.cn/problem/P3959)  
  Changed dimension: 访问集合仍在，但代价和层数/扩展顺序绑定。

Method summary: 凡是“把若干对象全部访问/排列一遍，并且代价和相邻关系有关”，优先想 `status + last`。

## 母题：[[081 Code01 每个人戴不同帽子的方案数]]

Mother-problem diagnosis: 这是小集合一侧压缩的匹配计数。帽子多、人少，所以压人，不压帽子。

Method core: 按帽子推进，`status` 表示哪些人已经分配到帽子；每顶帽子可以不用，也可以给一个喜欢它且尚未满足的人。

Selection lens: Model discriminator and unit recognition。先判断哪一侧规模小、哪一侧要被完全覆盖，再决定压哪一侧。

Test point: Key point: 不要看到“帽子编号 1 到 40”就压帽子；状态压缩要压小而关键的一侧。

Variants:
- Changed-representation variant: [LeetCode 1125. 最小的必要团队](https://leetcode.cn/problems/smallest-sufficient-team/)  
  Changed dimension: 人/帽匹配换成技能覆盖，状态表示已覆盖技能。
- Same-model variant: [LeetCode 1595. 连通两组点的最小成本](https://leetcode.cn/problems/minimum-cost-to-connect-two-groups-of-points/)  
  Changed dimension: 从计数变成最小代价，但仍然压小集合的覆盖状态。

Method summary: 两侧匹配/覆盖题先比较规模和目标：哪边小、哪边必须全部满足，就优先让哪边成为二进制状态。

## 母题：[[081 Code02 最优账单平衡]]

Mother-problem diagnosis: 这是集合内部消除问题。原始交易很多，但压缩前要先合并成每个人的净债务。

Method core: 先做状态归一化，再按集合判断能否内部清零，或用搜索不断消掉一个非零债务。

Selection lens: Transform-to-solvable。原始流水不能直接 DP，要先变成净债务数组，这一步才把问题变成状态压缩。

Test point: Key point: 这里的关键不是交易条数，而是归一化后还有多少个非零净债务人。

Variants:
- Changed-question variant: [LeetCode 1799. N 次操作后的最大分数和](https://leetcode.cn/problems/maximize-score-after-n-operations/)  
  Changed dimension: 从最少操作变成最大得分，但仍然是每次从未处理集合中取一组。
- Hidden-condition variant: [LeetCode 1681. 最小不兼容性](https://leetcode.cn/problems/minimum-incompatibility/)  
  Changed dimension: 子集合法性多了“不重复”和固定大小检查。

Method summary: 如果题面对象很多但可先合并，先归一化；归一化后的“小集合”才是状压入口。

## 母题：[[081 Code03 好子集的数目]]

Mother-problem diagnosis: 这是元素属性压缩题。状态位不代表数组下标，而代表质因子是否已经出现。

Method core: 把每个数字转换成质因子掩码，过滤含重复质因子的非法数，再做不相交掩码转移。

Selection lens: Unification axis。不同数字要先统一成同一种语言：质因子集合。统一后才能判断冲突和合并。

Test point: Key point: 先把值翻译成属性掩码，再 DP；不要直接拿原数做状态。

Variants:
- Changed-representation variant: [P1896 [SCOI2005] 互不侵犯](https://www.luogu.com.cn/problem/P1896)  
  Changed dimension: 从质因子冲突换成棋盘行内/行间冲突。
- Same-model variant: [P1879 [USACO06NOV] Corn Fields G](https://www.luogu.com.cn/problem/P1879)  
  Changed dimension: 用每一行的合法种植状态做掩码。
- Lens-specific upgrade variant: [P2704 [NOI2001] 炮兵阵地](https://www.luogu.com.cn/problem/P2704)  
  Changed dimension: 行间限制从上一行扩展到前两行。

Method summary: 当题目要求“选择的元素之间不能共享某种属性”，先把属性压成掩码，再用 `mask & state == 0` 判断能否合并。

## 母题：[[081 Code04 分配重复整数]]

Mother-problem diagnosis: 这是需求集合分配给资源频次。原数组不重要，重要的是每种值出现了多少次，以及哪些订单已经满足。

Method core: 统计频次，预处理每个订单子集的需求和，再枚举当前频次能满足哪个订单子集。

Selection lens: Model library mapping。题面是分配整数，本质模型是“资源容量覆盖需求集合”。

Test point: Key point: 订单才是状态单位；原数组里的每个数字不是状态单位。

Variants:
- Changed-question variant: [LeetCode 1494. 并行课程 II](https://leetcode.cn/problems/parallel-courses-ii/)  
  Changed dimension: 资源从数字频次换成每学期最多选课数，状态表示已完成课程。
- Changed-entry variant: [LeetCode 1879. 两个数组最小的异或值之和](https://leetcode.cn/problems/minimum-xor-sum-of-two-arrays/)  
  Changed dimension: 从满足订单变成一对一匹配，仍然用 `status` 表示右侧哪些对象已被使用。

Method summary: 分配题先判断状态单位：如果需求少，就压需求；如果右侧匹配对象少，就压右侧使用情况。

---

Reflection: 080/081 的状压题不应该只按“看起来像集合”来选。真正的选题准则是：同一个母题训练的状态单位是什么，变式就围绕这个单位做一层变化。Key point: 好变式保留方法核心，只改变外壳、问题目标、表示方式、隐藏检查或入口。
